# Company Foundry — Flywheel Model

**Status:** Phase 0 operational model. Not marketing copy. Not implemented.

This is the loop the company must be able to **run**, not merely describe.

---

## The loop

```txt
DISCOVER TALENT
  → GIVE SMALL REAL WORK
  → OBSERVE EVIDENCE
  → GIVE FEEDBACK
  → INCREASE RESPONSIBILITY
  → PAY FOR REAL VALUE          ← human gate
  → DEVELOP SPECIALIZATION
  → DEVELOP LEADERS
  → LET LEADERS DEVELOP OTHERS
  → STRONGEST PEOPLE BUILD PRODUCTS / TEAMS
  → COMPANY CREATES MORE REVENUE / CAPACITY
  → MORE PEOPLE CAN BE PAID
  → BEST DEVELOPED LEADERS MAY ENTER LONG-TERM OWNERSHIP CONVERSATIONS
  → THEY HELP FIND / DEVELOP THE NEXT COHORT
  → FLYWHEEL ACCELERATES
```

Each arrow is an **operation** with an owner, an input, an output, and (where marked) a human decision.

---

## Why this is not recruiting software

Recruiting software optimizes: stranger → application → interview → hire / reject.

This flywheel optimizes: stranger → demonstrated work → developed capability → created company value → that person develops the next stranger.

The last realization the experience is designed for:

**They're building the company out of the people who come through it.**

If the system only ever produces a nicer applicant inbox, the flywheel has failed.

## Operational stations

| Station | Input | Work | Output | Software role | Human role |
|---|---|---|---|---|---|
| Discover | Anonymous walk-ins, shares | Mystery door, notice, mess | Sessions + early evidence | Run the door | None required |
| Small work | Interested participants | Artifact tracks, return challenges | Artifacts + revisions | Host work, store evidence | Optional review |
| Observe | Evidence ledger | Organize, filter, summarize | Reviewable factual record | Organize only | Read |
| Feedback | Artifact + mentor/staff note | Specific, work-grounded notes | Feedback events | Deliver + track incorporation | Write feedback |
| Responsibility | Proven follow-through | Harder missions, collaboration, lead | Stage progression | Unlock **eligibility**, not status | Authorize jumps to real work / pay |
| Pay | Material company value | Classification + agreement | Paid contributor | Flag “this looks like work” | Decide + contract |
| Specialize | Repeated evidence in a track | Deeper projects | Track record (still not a type label) | Filter by evidence | Name the craft in conversation |
| Lead | People + outcomes | Mentorship, cohort help | Next-person evidence | Show who helped whom | Appoint leads |
| Build products | Trusted people | Sandbox → supervised real work | Shipped internal/external value | Bound access | Authorize access |
| Revenue / capacity | Shipped value | Company operations (outside TF) | Ability to pay more people | Do not fake this meter | Founders / finance |
| Ownership talk | Long evidence + trust | Legal / business conversation | Agreement or not | Preserve the trail | Founders only |
| Next cohort | Leaders + share door | Invite, mentor, select | New cohort | Cohort objects | Open cohort, invite, select |

## What the software must eventually support (not Phase 1)

1. A living evidence ledger per person (see evidence model).
2. Work objects with definition of done, mentor, status, revision.
3. Cohort objects with members, projects, stage, human decisions.
4. Auditable human gates for invite / pay / employ / lead / ownership talk.
5. A share door that starts strangers without giving referrers an advantage.
6. A command center that shows the funnel **and** the work, not just applicants.

What the software must **never** do:

- Auto-spin the flywheel (auto-pay, auto-hire, auto-equity).
- Display a “flywheel score.”
- Tell a participant they are “in the flywheel” as a gamified status.
- Imply that finishing stages produces revenue or ownership.

## Compensation path (do not blur)

| Mode | Is it employment? | Who decides | What TF may say |
|---|---|---|---|
| Learning / exploration | No | Participant | You’re looking around |
| Voluntary challenge | No | Participant | You’re making something |
| Paid project | Yes, if it is work — classify correctly | Human + agreement | Only after offer |
| Internship / apprenticeship | Yes | Human + agreement | Only after offer |
| Employment | Yes | Human + agreement | Only after offer |
| Leadership | Role, usually paid | Human | Appointment, not a badge drop |
| Ownership / partnership discussion | Separate legal event | Founders + counsel | Never as a completion prize |

If simulated or sandbox work starts producing material company value, the command center **flags compensation/legal classification** for explicit human review.

---

## Ownership path (do not blur)

This is **not**: complete Talent Foundry and earn equity.

This is: some people may eventually create enough sustained company value, responsibility, leadership, and trust that founders choose to discuss a long-term ownership relationship.

Recovered adjacent canon (`FOUNDER_EXECUTIVE_BOOK`, inventory): partner conversations and apprentice training already exist as **company operating ideas**. `@foundry/ownership-graph` is **not** this path (it is user–entity identity).

Talent Foundry preserves the **evidence of the journey**. Ownership remains an explicit legal/business decision outside the product.

---

## Acceleration (what “the flywheel accelerates” means)

Measurable operations, not vibes:

- More remembered participants complete return work.
- More cohort members finish delivered work after feedback.
- More people help the next person (multiply).
- More supervised work ships without expanding secret/data access.
- More paid hours are tied to delivered value (human-classified).
- More leaders spend time developing people than consuming tasks.
- Share door brings strangers who stay past NOTICE — without referral scoring.

If those numbers rise while human gates stay human, the flywheel is real.
